# AI 游戏美术经验沉淀与坑点避指南 (MEMORY)

## 1. 2026 AI 游戏美术核心坑点 (Common Pitfalls)

1. **“一键生成即商用”的幻觉**：
   - 绝大多数 AI 生成的 3D 模型存在非流行流形（Non-manifold）、重叠三角面、乱乱布线和高面数问题，直接导入引擎会导致渲染过载和碰撞物理失效。必须经过 DCC (Blender) 重拓扑（Retopology）。
2. **风格漂移 (Style Drift)**：
   - 纯靠 Prompt 无法维持跨资产（如 50 个不同道具/角色）的视觉一致性。工业管线必须依赖私有化 LoRA 微调 + ControlNet 姿态/线稿约束 + Seed 锁色。
3. **2D 序列帧/动画不连贯**：
   - AI 生成 2D 序列帧容易出现微小闪烁和形变。当前最佳工程解法是：AI 生成高精度静止帧 ➔ 拆分图层 ➔ 导入 Spine / Live2D 进行传统骨骼绑定与动效制作。
4. **版权与商用法律风险 (2026 强监管现状)**：
   - 公共模型直接生成的内容在部分国家/地区不受版权保护，或存在数据训练源侵权风险。成熟团队普遍采用私有数据微调模型，并保留全套人机协同修改草稿过程备查。

## 2. 阶段二实测探索目标 (Stage 2 Benchmark Target)
- **基准测试项目 (Benchmark Target)**：**“单场景切片验证 (Mini-Slice Test)”**
  - **切片内容**：1个角色 (2D/3D) + 3个关联道具 (3D) + 1组场景连续贴图 (PBR) + 1组 UI 图标。
  - **测试目的**：通过端到端实测验证 AI 工具链的资费门槛、生成速度、引擎无缝导入准备度及跨资产视觉一致性。

## 3. 验证阶段技术选型准则 (Verification Phase Strategy)
- **原则：商业 SaaS 优先 (SaaS First in Verification Phase)**
  - 验证阶段的核心目标是**玩法验证与管线体验**，而非成为 AI 运维工程师。
  - 商业 SaaS (Tripo3D, Meshy 6, Scenario.gg, Midjourney) 封包了自动拓扑、UV展开、透明扣图与极佳 UX 体验，是验证期的**效率与体验天花板**。
  - 只有在未来跨入大规模量产（需批处理几百个资产或节省订阅成本）时，才需考虑搭建本地 ComfyUI / 开源模型。

## 4. 三工具实测组合 (The 3-Tool Benchmark Suite)
- **Tripo3D (tripo3d.ai)**：3D 极速建模 (单图转 3D 网格)
- **Meshy 6 (meshy.ai)**：3D 高精材质与 PBR 贴图生成
- **Scenario.gg (scenario.com)**：2D 角色/UI/透明背景 Sprite 批处理
