## 🎮 一、 饥荒 Mod 现代开发与 UI 测试方法论 (DST Testing & Dev Strategy)

### 1. 为什么“无头专用服务器 (Nullrenderer)”无法直接测 UI？
* **物理边界**：`dontstarve_dedicated_server_nullrenderer_x64.exe` 是纯服务端（Server-only），底层没有图形渲染管道（`TheFrontEnd == nil`）。
* **职责分工**：
  - **无头服务器负责 90% 后端逻辑**：世界生成、组件初始化（`SimPostInit`）、数据存盘（`OnSave/OnLoad`）、网络 RPC 序列化与路由；
  - **客户端负责 10% 界面渲染**：所有 `widgets/` 与 `screens/` 代码只有在客户端真正在屏幕上弹窗时才会执行。

### 2. 为什么坚决不做“重型虚拟客户端沙盒 (Mock Client)”？
* **陷阱**：在命令行里手写几百行 Mock 桩去伪造 C++ `Widget` 树、字体渲染和鼠标碰撞箱，属于高成本低回报的“过度工程”，会严重偏离业务开发主线。

### 3. 黄金标准架构：【双层防御体系 + F5 秒级热重载】
1. **第一道防线（无头后台离线跑测 `-offline`）**：
   - 自动检测并拦截所有可能导致游戏崩溃、无法进入房间的底层世界/RPC/语法致命伤；
2. **第二道防线（游戏内轻量自检探针 `c_test_atlas()`）**：
   - 在 `modmain.lua` 内置 15 行宏指令，在游戏内按顺序触发 `OpenAtlasBook()` 与 `AddTask()`，秒级检测 Lua 运行时错误；
3. **免重启闭环（F5 热重载）**：
   - 遇到任何 UI 调整，在游戏内直接按 **F5 重置世界**（1 秒生效），彻底消除“闪退 ➔ 重启 Steam ➔ 重新进房（耗时 1 分钟）”的巨大心智磨损。

## 🛠️ 二、 饥荒 Mod 核心避坑切片 (DST Critical Pitfalls)

| 序号 | 痛点现象与物理根因 | 官方标准正解 (Source of Truth) |
| :---: | :--- | :--- |
| **1** | **`AddPlayerPostInit` 的 `TheWorld == nil` 陷阱**<br>开局发道具静默失效，因实体首帧 `TheWorld` 尚未生成。 | 必须在 `inst:DoTaskInTime(0.5, ...)` 内部或直接用 `inst.ismastersim` 判定，且 0.5s 延迟能完美避开重进存档时的背包覆盖。 |
| **2** | **文件夹 `workshop-` 前缀的引擎级类型锁**<br>改了本地 Mod 名字在游戏里不刷新，因引擎强制将 `workshop-` 目录作为整型工坊 ID 解析。 | 本地开发 Mod 必须命名为非 `workshop-` 开头的纯净目录（如 `atlas_book_local`）。 |
| **3** | **严格模式下的全局引用与组件环境**<br>在 `scripts/components/*.lua` 里写 `GLOBAL.json` 报错未声明。 | `GLOBAL` 仅为 `modmain.lua` 注入的局部包装；在 `scripts/` 内部组件与 UI 文件中，系统全局符号直接位于根 `_G`（直接调用 `json` / `_G`）。 |
| **4** | **纯客户端告示牌弹窗 (`WriteableWidget`) 范式**<br>客机非法 `SpawnPrefab("homesign")` 实体缺少服务端组件导致静默短路。 | 官方 `WriteableWidget` 是纯客户端 Screen 窗口，传一个虚拟 `CreateEntity()` 即可直接弹出原版木牌界面，无需生成世界物理实体。 |

## 🎨 三、 AI 游戏美术经验沉淀 (Common Pitfalls)

1. **“一键生成即商用”的幻觉**：3D 模型非流行流形问题必须经 Blender 重拓扑。
2. **风格漂移 (Style Drift)**：跨资产需依赖私有化 LoRA + ControlNet 约束。
3. **2D 序列帧不连贯**：高精度静止帧 ➔ 拆分图层 ➔ Spine/Live2D 骨骼绑定动效。
